# 账号与准入

重要度：★★★。阅读基线见 [[源码地图]]，先尝试 [[账号与准入练习]] 再展开答案。

## Purpose · 职责

身份来自登录会话，自带服务密钥不承担身份认证。UserId 依赖要求登录且已同意条款；Admissions 在每次文字回合或通话开始时选定密钥、记录并占用限额，结束时只结算一次。

## Key Files · 关键源码

| 源文件（项目根目录相对路径） | 职责 |
|---|---|
| `backend/src/eidolon/sessions.py` | Cookie、Origin、UserId 与同意条款 |
| `backend/src/eidolon/account_api.py` | OAuth、开发登录、账号和自带密钥校验接口 |
| `backend/src/eidolon/accounts.py` | 账号关联、退出与删除 |
| `backend/src/eidolon/admission.py` | 密钥、运行记录、限额与结算的共同入口 |
| `backend/src/eidolon/usage.py` | 小时限额、通话时长与次数 |
| `backend/src/eidolon/identity.py` | Google/GitHub 适配 |

## Public Interface · 对外边界

| 入口 | 行为 |
|---|---|
| `signed_in_user` / `current_user` | 401 未登录、403 封禁、428 尚未同意 |
| `/api/auth/{provider}/start` / `callback` | 短期 state cookie 约束 OAuth 回调 |
| `Admissions.turn` / `call` | 冷却检查 → 取得密钥 → 建记录 → 占限额 |
| `Admission` 结算 | 依结果保留或退还占用、写记录、释放租约 |

## Internal Flow · 内部流程

```text
browser -> same-origin proxy -> session cookie + Origin check
        -> SignedIn -> consent -> UserId -> ownership check
        -> Admissions -> OwnKeys -> activity -> usage
        -> engine / call -> outcome -> settle once
```

## Configuration · 配置

| 变量 | 用途 |
|---|---|
| `GITHUB_CLIENT_ID/SECRET`、`GOOGLE_CLIENT_ID/SECRET` | OAuth 应用 |
| `EIDOLON_DOMAIN` | 生产域名、Cookie Secure 与公网边界 |
| `EIDOLON_DEV_LOGIN` | 本地开发登录开关 |
| `EIDOLON_SECRET_KEY` | 服务端密钥加密等用途 |
| `EIDOLON_TURNS_PER_HOUR`、`EIDOLON_CALLS_PER_HOUR` | 部署限额；后台可覆盖 |

## Testing · 如何验证

在 `backend/`：`uv run pytest tests/test_sign_in.py tests/test_consent.py tests/test_data_access.py tests/test_admission.py tests/test_rate_limit.py`。OAuth/外部服务使用替身；读取权限还应查 `test_past_conversations.py` 等业务用例。

> [!warning] 边界与常见误读
> 会话 cookie 是 httpOnly、SameSite=Lax，生产还带 Secure；改变状态的请求另查 Origin。文字 success/left 与通话 success/failed 是准入层保留用量的结果集合，具体是否开口、接通由 Outcome 决定；不能只看 HTTP 200 推断消费。跨用户对话查询返回 404。
