# 记忆与搭话

重要度：★★★。阅读基线见 [[源码地图]]，先尝试 [[记忆与搭话练习]] 再展开答案。

## Purpose · 职责

记忆属于用户，跨角色共享但保留最初告知的角色；后台模型只提炼值得保留的用户事实。搭话是在当前对话中主动留下的话，使用部署模型，有自己的记录和开关，不算用户主动回合。

## Key Files · 关键源码

| 源文件（项目根目录相对路径） | 职责 |
|---|---|
| `backend/src/eidolon/memory.py` | 检索、后台提炼、替代关系与清空防复活 |
| `backend/src/eidolon/reach_outs.py` | 离线搭话候选、夜间避让与调度 |
| `backend/src/eidolon/engine.py` | 成功回合后 write_down 与专用 reach_out |
| `backend/src/eidolon/store.py` | 搭话记录及当前对话的并发复核 |
| `docs/adr/0002-shared-memory-with-source-character.md` | 同一用户跨角色共享、保留来源 |
| `docs/adr/0014-superseded-memories-are-marked-not-rewritten.md` | 保留被替代事实 |
| `docs/adr/0026-reach-outs-are-not-turns.md` | 搭话不是用户回合 |

## Public Interface · 对外边界

| 入口 | 用途 |
|---|---|
| `Memories.begin` → MemoryTurn | 等待上轮提炼一小段时间，建立本轮上下文 |
| `candidates/find/write_down` | 向量候选 → 重排 → 成功回合后后台提炼 |
| `entries/delete/clear` | 本人查询与删除，不提供任意编辑接口 |
| `ReachOuts.keep_reaching_out` | 持续检查满足条件的当前对话 |
| `ConversationEngine.reach_out` | 生成独立搭话，不伪造用户消息 |

## Internal Flow · 内部流程

```text
recorded turn -> background extraction -> memory + vector + source character
next turn -> query -> holding memories -> rerank -> hearsay prompt
new fact --supersedes--> old fact (kept, not retrieved)

last contact + tier interval -> reach-out tick -> eligibility
 -> deployer LLM -> recheck contact/current conversation -> ReachOut record
```

## Dependencies · 依赖方向

- 使用：[[模型协议与自带密钥]]的后台模型、[[检索与剧情同步]]的向量/重排、[[运行时装配与数据库]]。
- 被使用：[[对话引擎]]、[[数据包与备份]]、[[前端导航与会话状态]]。
- 搭话还依赖 [[好感度玩法与日历]]的档位与用户时区。

## Configuration · 配置

| 配置 | 行为 |
|---|---|
| `BACKGROUND_LLM_*` | 记忆提炼模型 |
| `EIDOLON_REACH_OUTS` | 部署开关，实际值见实时配置 |
| 账号 reach_outs 开关 | 用户可以单独关闭 |
| profile.timezone | 夜间与早晨安排；无配置用 Asia/Shanghai |
| `SETTLE_TIMEOUT` | 当前记忆等待上限 5 秒，不保证无限等完 |

## Testing · 如何验证

在 `backend/`：`uv run pytest tests/test_shared_memory.py tests/test_memories.py tests/test_memory_management.py tests/test_reach_outs.py tests/test_reach_outs_in_turns.py`。用 fake clock 测试时区、夜间、重启错过和联系竞争；不要等待真实数小时。

> [!warning] 边界与常见误读
> 删除新事实可能让被它替代的旧事实恢复为 holding；不等于旧事实被重写。清空会阻止旧的在途提炼重新写回。新对话只通过检索到的记忆承接旧事，不自动携带全部历史。搭话不会补发启动前错过的计划，也不在用户回合/通话正在进行时打扰。
