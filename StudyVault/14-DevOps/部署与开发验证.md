# 部署与开发验证

重要度：★★★。阅读基线见 [[源码地图]]，先尝试 [[部署与开发验证练习]] 再展开答案。

## Purpose · 职责

本地从最小文字聊天逐项开启外部能力；生产是 Linux VPS 上四服务 host 网络。CI 验证工程契约并发布镜像，浏览器/真实服务测试则单独验证界面和线上行为。

## Public Interface · 对外边界

| 接口/命令 | 用途 |
|---|---|
| `uv run --env-file=../.env eidolon serve` | backend 工作目录启动 |
| `npm run build` / `npm run start` | frontend 构建版启动 |
| `docker compose up --build` | 本地 compose |
| `docker compose -f docker-compose.prod.yml pull` | 生产取镜像，下一步 up 才应用 |
| `GET /api/health` | 独立连接可读性，200 或 503；不是模型探活 |

## Internal Flow · 内部流程

```text
browser -> Caddy HTTPS -> Next frontend -> FastAPI (loopback)
       \------------------- WebRTC / TURN -> backend

PR / main push -> backend + frontend + shellcheck + image builds
main/tag push + all checks -> GHCR publish -> operator deploy
```

## Configuration · 配置

| 配置 | 含义 |
|---|---|
| 最小文字配置 | CHAT_LLM_BASE_URL/API_KEY/MODEL + 本地开发登录 |
| `EIDOLON_DOMAIN/PUBLIC_IP/PRIVATE_IP` | 生产 HTTPS 与 ICE/NAT 地址 |
| `EIDOLON_TURN_SECRET/MIN_PORT/MAX_PORT` | coturn 短期凭据与中继范围 |
| `EIDOLON_IMAGE_TAG` | 镜像固定版本；未设走 main |
| 版本 | 后端 Python >=3.11；CI 前端 Node 22；依赖以锁文件为准 |

## Testing · 如何验证

后端 `uv sync --locked`、`uv run ruff check`、`uv run pyright`、`uv run pytest`；前端 `npm ci`、`npm run typecheck`、`npm test`；在 Git Bash/WSL 执行 `sh scripts/check-discipline.sh`。CI 还跑 shellcheck、scratch 检查并构建两个镜像。重活应串行运行。

> [!warning] 边界与常见误读
> 生产 host 网络拓扑针对 Linux VPS，不应照搬为 Windows 本地方案。容器 unhealthy 不会自动重启。改前端后先停旧 :3000、再构建、再起，避免旧子进程仍服务旧页面；只结束父 shell 不一定释放端口。真实密钥调用可能计费，本学习库不自动触发。
