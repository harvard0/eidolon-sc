# 运行时装配与数据库

重要度：★★★。阅读基线见 [[源码地图]]，先尝试 [[运行时装配与数据库练习]] 再展开答案。

## Purpose · 职责

这是带模块边界的单进程后端。装配根决定哪些能力开启，数据库层把 SQL 留在领域模块内，只负责在线程上执行事务，避免所有通话共用的事件循环等待 SQLite。

## Key Files · 关键源码

| 源文件（项目根目录相对路径） | 职责 |
|---|---|
| `backend/src/eidolon/__main__.py` | CLI 分派、模型启动检查与 uvicorn |
| `backend/src/eidolon/assembly.py` | build 装配、Backend.start/aclose |
| `backend/src/eidolon/data_access.py` | Database：一个写线程、默认四个只读连接 |
| `backend/src/eidolon/database.py` | 连接参数、删除边界与独立健康读取 |
| `backend/src/eidolon/store.py` | 用户、会话、对话、消息、事件、照片及通话记录 |
| `docs/adr/0028-one-writer-thread-no-database-on-the-event-loop.md` | 线程、事务和例外的决策依据 |

## Public Interface · 对外边界

| 入口 | 契约 |
|---|---|
| `build(Settings, ...)` | 可注入外部服务替身，返回 Backend |
| `Backend.start()/aclose()` | 启动后台循环；停任务并按逆序释放自建资源 |
| `Database.read(body, *args)` | 在线程池只读快照内执行同步事务体 |
| `Database.write(body, *args)` | 交给唯一写线程；成功提交，异常回滚 |
| `Database.checkpoint()` | 清理 WAL，短等待后重试 |

## Internal Flow · 内部流程

```text
Settings -> build -> Backend -> create_app -> lifespan
                     |             |
                     |             +-> start / aclose
+--------------------+---------------------------+
| event loop: await read / write; never run SQL   |
+-----------+--------------------+---------------+
            |                    |
    read-only pool          FIFO writer thread
            |                    |
            +---- SQLite WAL ----+
```

## Dependencies · 依赖方向

- 使用：配置、角色、[[模型协议与自带密钥]]、[[检索与剧情同步]]等全部服务。
- 被使用：[[账号与准入]]、[[对话引擎]]、[[实时通话]]、[[管理与运行观测]]。
- 事务体返回业务结果，回到事件循环后再通知通话；不要在事务体读循环状态或触发回调。

## Configuration · 配置

| 项 | 值或来源 |
|---|---|
| `EIDOLON_DATABASE_PATH` | 默认 `data/eidolon.db`，相对后端工作目录 |
| `EIDOLON_CHARACTERS_PATH` | 默认 `../characters/characters.toml` |
| `READERS` / `THREADS` | 源码默认 4 个读连接 / 32 个默认执行器线程 |
| SQLite | WAL、NORMAL、secure_delete、foreign_keys |

## Testing · 如何验证

在 `backend/` 执行：`uv run pytest tests/test_data_access.py tests/test_database.py tests/test_assembly.py tests/test_all_or_nothing.py`。测试会让事件循环线程取连接直接报错；事务测试要检查整体回滚，不能只检查单表。

> [!warning] 边界与常见误读
> 取消 await 不撤回已提交给写线程的任务。健康检查另开只读连接，备份 VACUUM INTO 另开连接，这两个是有意的例外。WAL + NORMAL 仍可能在断电时丢失最近提交。当前设计仍是单进程，不能直接把 uvicorn workers 调大并假设通话状态共享。
