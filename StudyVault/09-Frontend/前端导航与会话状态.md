# 前端导航与会话状态

重要度：★★★。阅读基线见 [[源码地图]]，先尝试 [[前端导航与会话状态练习]] 再展开答案。

## Purpose · 职责

前端采用 Next.js App Router。导航外壳持有目录及正在通话的 LiveConversation，页面订阅 React 外的快照，离开角色页但仍在外壳内时电话继续。落地页是独立视觉区域。

## Key Files · 关键源码

| 源文件（项目根目录相对路径） | 职责 |
|---|---|
| `frontend/src/app/(app)/(nav)/layout.tsx` | DirectoryProvider 与 NavShell 的共同生命周期 |
| `frontend/src/components/conversations/ConversationDirectory.tsx` | 目录、账号、持有通话与去处规则 |
| `frontend/src/lib/liveConversation.ts` | React 外的 LiveConversation 状态与订阅快照 |
| `frontend/src/lib/conversationLog.ts` | 记录与暂态增量归并 |
| `frontend/src/lib/navShell.ts` | 离开外壳、切换角色的导航判断 |
| `frontend/src/app/api/[...path]/route.ts` | 同源流式 API 代理 |
| `frontend/src/app/(landing)/LandingEntry.tsx` | 独立落地页入口与延迟登录面板 |
| `frontend/AGENTS.md` | Base UI、token、组件归属和纪律检查 |
| `DESIGN.md` | 视觉规范唯一依据 |

## Public Interface · 对外边界

| 边界 | 职责 |
|---|---|
| DirectoryProvider / useDirectory | 账号、角色、摘要、held、open/close/go/guard |
| LiveConversation | 发送、通话、字幕、照片与结束卡状态 |
| NavShell / CallLayer / ConversationView | 渲染与用户操作 |
| `lib/api.ts` | 请求、错误、时区、SSE 类型及解析 |
| catch-all route | 转发 body 流、cookie、Origin 和 Set-Cookie |

## Internal Flow · 内部流程

```text
(nav)/layout -> DirectoryProvider -> held LiveConversation
                         |                  | snapshots
                         v                  v
                      NavShell ------> ConversationView / CallLayer
                         |
                    api / call -> same-origin proxy -> backend

landing route group -> own visual world + delayed sign-in panel
```

## Configuration · 配置

| 项 | 约束 |
|---|---|
| `BACKEND_URL` | 服务端默认 http://localhost:8000，不直接暴露到浏览器 |
| `EIDOLON_STAND_ASSETS_URL` | 前端也要配置，用于资源域与 CSP |
| `components/ui/` | shadcn 源码，Base UI，base-nova；修改处用 eidolon 注释 |
| Tailwind v4 / herVars | 具名主题 token；角色色注入子树，浮层考虑 portal 继承 |
| `lib/localOwnKeys.ts` | 按用户本机保存，请求时现读 |

## Testing · 如何验证

在 `frontend/`：`npm run typecheck`；`npm test -- src/lib/liveConversation.test.ts src/lib/navShell.test.ts src/lib/conversationLog.test.ts`；Git Bash/WSL 运行 `sh scripts/check-discipline.sh`。组件改动的浏览器验收遵循 `docs/agents/local-acceptance.md`，不能把纯逻辑 Vitest 当成页面验收。

> [!warning] 边界与常见误读
> React 组件卸载不必然挂断：外壳会保留通话及未关闭的结束卡；跳到另一角色或外壳外则有挂断规则。整页 reload 仍会断开。目录前台轮询为 60 秒，照片等待为 2 秒，并非服务器给所有页面推送所有更新。项目没有 ESLint 脚本。
