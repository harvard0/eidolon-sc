# 管理与运行观测

重要度：★★★。阅读基线见 [[源码地图]]，先尝试 [[管理与运行观测练习]] 再展开答案。

## Purpose · 职责

后台通过运行数据管理服务、模型、限额、用户、公告、赞赏码和备份。运行记录关注成功失败、耗时、用量和费用估算，不提供查看用户谈话与记忆的管理功能。未登录、无管理权限、尚未同意条款或部署未配置管理员时，管理路由统一返回 404。

## Key Files · 关键源码

| 源文件（项目根目录相对路径） | 职责 |
|---|---|
| `backend/src/eidolon/live_config.py` | 环境基线、加密覆盖、启动重试与恢复 |
| `backend/src/eidolon/admin_api.py` | 管理员入口 |
| `backend/src/eidolon/admin_config_api.py` | 配置查询/修改/恢复路由 |
| `backend/src/eidolon/activity.py` | 活动与服务调用记录，不保存谈话内容 |
| `backend/src/eidolon/dashboard.py` | 部署使用看板与正在通话 |
| `backend/src/eidolon/stats.py` | 用户自己的对话/通话/礼物统计 |
| `backend/src/eidolon/service_status.py` | 探测和窗口状态 |
| `backend/src/eidolon/prices.py` | 按调用用量估算花费 |
| `backend/src/eidolon/announcements_api.py` | 公告草稿、发布与置顶 |
| `backend/src/eidolon/sponsor_api.py` | 赞赏码配置和图片 |

## Public Interface · 对外边界

| 接口或类型 | 说明 |
|---|---|
| LiveConfig | `.env` 基线 + 数据库覆盖，按 item 变更与恢复 |
| `/api/admin/dashboard` / `/calls/live` | 管理看板与进行中通话 |
| `/api/admin/users/...` | 用户、封禁/解除、限额与删除 |
| `/api/service-status` | 用户可见服务窗口状态 |
| ActivityLog / Billing / Prices | 业务活动、外部服务请求、估算账单 |
| `/api/stats` | 用户本人统计，和管理看板边界不同 |

## Internal Flow · 内部流程

```text
env -> Settings -> LiveConfig <- encrypted db overrides
admin change -> try service -> persist -> swap / next admission

turn / call / reach-out -> activity record
external request -> service call + Billing -> Prices -> dashboard
status probes + recent activity -> visible service status
```

## Configuration · 配置

| 变量 | 影响 |
|---|---|
| `EIDOLON_ADMINS` | 按登录 provider:subject 标识管理员 |
| `EIDOLON_SECRET_KEY` | 派生覆盖配置的密钥加密材料 |
| `EIDOLON_STATUS_SERVICES/WINDOW_MINUTES` | 用户服务状态范围 |
| 后台配置项 | 模型、语音、限额、阈值、代理、玩法与搭话等 |
| 价格目录 | 估价来源与覆盖，不保证等同提供商最终账单 |

## Testing · 如何验证

在 `backend/`：`uv run pytest tests/test_live_config.py tests/test_live_config_services.py tests/test_admin_entry.py tests/test_activity_records.py tests/test_service_status.py tests/test_stats.py`。用替身验证改配置时先试用、失败回退和旧租约释放。

> [!warning] 边界与常见误读
> 启动时无效覆盖会保留并标失败，使用环境基线，避免管理后台无法启动。运行时配置成功只影响之后开始的回合/通话，旧租约不变。一次业务可对应多次服务尝试，后台任务也可能独立记录；不能把 service call 总数当用户回合数。
