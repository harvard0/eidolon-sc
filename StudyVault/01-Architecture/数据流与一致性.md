# 数据流与一致性

## 输入、处理、落库、输出

| 数据 | 进入与处理 | 持久位置 | 输出与权限 |
|---|---|---|---|
| 用户消息、角色日中分段 | 本轮模型与格式解析 | Store 消息表 | SSE/数据通道、本人历史 |
| 好感度、任务奖励 | judge + 领域规则 | 同一业务事务 | 档位、变化标签、玩法状态 |
| 记忆 | 成功回合后后台模型提炼 | memories + vectors + 替代关系 | 本人管理，跨角色来源转述 |
| 剧情、事实、向量 | 私有源导入/同步、embedding | 剧情/向量与事实相关表 | 受角色范围约束进入本轮 prompt |
| 照片 | tag → 排队 → 生图 | SQLite 图像和状态 | 本人照片 API，数据包 |
| 自带密钥 | 浏览器每次传入 | 浏览器 localStorage；服务端不持久化 | 本轮/通话及后台派生任务临时持有 |
| 实时配置覆盖 | 管理员试用后保存 | DB，敏感 key 加密 | 管理权限，旧请求保留租约 |
| 运行记录 | Outcome、计量包装器 | 活动和外部服务记录 | 管理看板，不存谈话正文 |
| 通话对象、字幕暂态 | 客户端/后端状态机 | 运行时内存 | 当前浏览器；已结算通话另有持久记录 |

```text
                streamed delta -> ephemeral UI
               /
LLM -> complete segments -> writer transaction -> persisted reply -> done
                                  |                  |
                        affinity/photo/reward     memory/title tasks
                                                    (separate writes)

photo generation -----------------> associated reply + picture/status
```

## 事务边界

[[对话引擎]] `_record` 将双方消息、好感度、照片引用、玩法进度与奖励一起提交。[[好感度玩法与日历]]的送礼、抽奖、重置等路径也用所属业务事务；跨模块复用同一连接的事务体，不另开“补偿式”独立写入。

后台提炼、标题、最终图像及运行记录不全属于那次原子提交；它们可以稍后完成或失败。[[管理与运行观测]]的记账失败不应把已保存回合倒回去。[[数据包与备份]]导入先离库准备，再一次提交。

## 取消、删除与一致性

> [!warning] 取消不是数据库回滚命令
> 排进 Database.write 的任务会执行完，即使等待它的协程已取消。引擎对提交阶段用保护和后续通知，避免用户离开后事务结果无人处理。网络断开、协程取消、业务拒绝和模型 stop 是不同事件。

| 操作 | 保留或清理规则 |
|---|---|
| 新建对话 | 不复制完整旧历史；靠检索到的记忆延续 |
| 记忆 clear | 失效旧在途提炼，防止写回已清空事实 |
| 记忆 supersede | 旧行保留但不作为 holding 检索，可因删除新事实恢复 |
| 删除用户 | 删除所属数据，secure_delete + WAL checkpoint；已下载数据包不受控制 |
| 删除历史对话 | 不倒扣已赚任务成就；照片随相关数据处理 |
| 导入历史 | 不重放业务事件赚取奖励，不移植当前好感/背包 |

## 日期不是一个全局值

角色生日与日本节假日按东京；制作人生日按其有效本地日；任务与每日抽奖按北京；搭话夜间按档案时区，默认上海。见 [[好感度玩法与日历]] 和 [[记忆与搭话]]，不要把浏览器日期当全部服务端业务日期。
