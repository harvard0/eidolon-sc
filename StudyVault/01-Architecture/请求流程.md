# 请求流程

## 一轮文字聊天

```text
UI send
 -> LiveConversation -> lib/api.sendTurn
 -> POST /api/conversations/{id}/turns (Next catch-all proxy)
 -> session + consent + conversation owner
 -> Admissions: cooldown -> keys -> activity -> quota
 -> engine.turn: trim + validate
 -> db.read: record/profile/affinity/photo eligibility
 -> memory.begin + retrieval.retrieve
 -> prompt -> LLM stream -> ReplyParser
 -> SSE: user -> [photo] -> delta* -> [photos-used-up] -> done
 -> db.write: both messages + affinity + photo reference + rewards
 -> background memory + title
```

图中的 SSE 箭头表示整个流输出，**done 一定在数据库成功提交之后**；delta 可以早于提交。通常异常变成流内 error，未成功记录的普通回合不改变好感度。准入、模型和持久化分别查 [[账号与准入]]、[[模型协议与自带密钥]]、[[运行时装配与数据库]]。

## 一通电话

```text
getCallSetup / GET ice-servers
 -> mic + local offer
 -> POST offer(requestData) -> Calls.start -> admissions
 -> answer + PATCH ICE -> connected
 -> input audio -> STT final text -> TurnTaking / CallTurns
 -> same engine -> ja to TTS, ja/zh events to data channel
 -> output audio + subtitle state -> next utterance
 -> user/limit/failure/character end -> CallOutcome.settle
```

[[实时通话]]里的 connected 才启动时长计时。角色被打断时 stop 结束模型等待，已完成分段可以记录；这和普通模型异常不同。只看文字和麦克风静音是两个方向的控制。

## 典型失败落点

| 发生位置 | 对外形式 | 排查起点 |
|---|---|---|
| 会话/同意 | 401 / 428 | sessions.py、api.ts |
| 对话属于别人/已删除 | 404 | conversation_or_404 |
| 冷却、已结束或重复拨号 | 409，按 detail/字段区分 | app.py、admission.py |
| 小时限额 | 429，可含 retry_at / Retry-After | usage.py、admission.py |
| 通话未配齐/并发已满 | 503；并发满有 calls_busy | app.py、Calls |
| 已进入文字流的模型失败 | SSE error | engine.turn、OwnKeyFailed |
| 检索依赖失败 | 尽可能降级继续，不等于回合必失败 | retrieval.py、memory.py |
| 写入失败 | 不发成功 done；业务事务回滚 | engine._record、Database.write |

## 阅读时验证的四个问题

- 哪一层判断“这个人是谁”？在 sessions 与业务所有权检查。
- 哪一层决定“花谁的钱”？在 OwnKeys 与 Admissions。
- 哪一刻“已保存”？在成功业务事务，而非 first delta 或音频开始。
- 哪一层“可换页但不挂断”？在 DirectoryProvider 持有状态，见 [[前端导航与会话状态]]。
